## Outcome
Launch a small, polished **Vowora marketing website immediately** at **vowora.app**, using the **existing Vercel project**. The public root route `/` remains the marketing homepage while the authenticated wedding planning application is built in subsequent steps. Do not replace the homepage with the app later without explicit owner approval.

## Preflight — inspect, don't recreate
1. Inspect the repository, existing Next.js/Vercel setup and deployment configuration. Reuse the existing Vercel project, its linked repository and any verified custom domain. Do **not** create a second Vercel project, purchase or guess a domain, change DNS blindly or assume a domain from the brand name.
2. The approved production domain is **vowora.app**. Verify that this domain is connected to the existing Vercel project and that DNS/HTTPS are correctly configured; report any owner action needed. Do not infer that the domain is already connected just because it was purchased.
3. Inspect existing logo/brand assets in the repository and use the approved Vowora branding rather than generating or replacing assets without approval.
4. Follow the existing architecture's initial Vercel/Next.js deployment. If the monorepo isn't initialized yet, implement the smallest architecture-compatible website foundation without introducing a throwaway framework or requiring auth, Neon, Trigger.dev or other unbuilt app infrastructure.

## Marketing page — scope
- Public `/` with Vowora brand navigation, concise hero, clear description of wedding planning for couples and professionals, honest approved feature highlights, tasteful call to action, and a simple footer.
- Apply **VIS-004 Immersive Botanical**: sage/ivory/forest, layered restrained botanical visuals, coordinated light/dark modes, responsive layout and reduced-motion support.
- Feature descriptions must distinguish **planned** capabilities from those already live. Any dashboard preview must be clearly illustrative, accurate to the approved product scope and not falsely presented as a functioning app.
- Use a non-deceptive CTA (e.g. learn more/contact if an approved working destination exists); **do not invent** signup, waitlist, newsletter, booking, pricing, customer testimonials or email capture. If a CTA destination is unavailable, request a decision before implementing it.
- Add appropriate metadata, canonical URL only after domain confirmation, Open Graph/social preview when suitable assets exist, favicon, robots and sitemap as appropriate for a public marketing site.
- Preserve a future app route strategy (e.g. `/app` or a separate app subdomain **only after explicit routing decision**) without implementing a fake app, login or backend now.

## Not in scope
Authentication, wedding workspaces, database, paid plans, app modules, invented product promises, a second Vercel project or irreversible DNS changes.
